# CST3530 touch on the Lyra Zero W

The driver is tracked in `kernel/drivers/input/touchscreen/`. `lyra-build`
copies it during `prepare` and `sync-sources`; the tracked
`patches/cst3530-touch-integration.patch` adds Kconfig/Makefile entries.
`rk3506-squashfs.config` enables it built-in. Do not edit the SDK copies.

## Wiring

| Touch signal | Lyra Zero W connection |
| --- | --- |
| SDA | DSI H2 pin 2, already connected to GPIO0_A0 / I2C2 SDA |
| SCL | DSI H2 pin 3, already connected to GPIO0_A1 / I2C2 SCL |
| INT | GPIO0_A3 / GPIO 3 / RM_IO3 |
| RESET / RSTn | GPIO0_A4 / GPIO 4 / RM_IO4 |
| Adapter power | DSI H2 pin 1 provides 3.3 V; verify adapter requirements |
| Ground | GND |

GPIO numbers above are **not physical header pin numbers**. H2 numbers refer
to the 22-pin DSI connector, not the panel's 30-pin flex. See the
[official Zero W pinout](https://wiki.luckfox.com/Luckfox-Lyra/Pinout/).
INT has an internal pull-up and uses falling-edge interrupts. RESET is
active-low, separate from the panel reset on GPIO0_B5. A3/A4 are free in
this project's enabled device tree. I2C uses 400 kHz and address `0x58`.

The [official Zero W schematic](https://github.com/LuckfoxTECH/Luckfox-Lyra-docs/blob/main/Hardware/Schematic/Luckfox-Lyra-Zero-W.pdf)
shows SDA/SCL on H2 through 22-ohm resistors, with 3.3-kilohm pull-ups to
3.3 V. Separate SDA/SCL jumpers are unnecessary if the display adapter routes
these flex signals to the touch controller. The adapter's routing has not
been verified from a schematic.

The local `AM_319_M262928_ZS_3a5effae7d.pdf` drawing labels the **bare panel's**
30-pin flex differently: SDA on pin 26, SCL on pin 28, RESET on pin 22 and
INT on pin 24, all **1.8 V** signals; touch VCC on pin 18 is **2.8 V**.
The Lyra side is 3.3 V. Use an adapter with appropriate level translation
and power regulation; do not connect the bare panel's touch signals or VCC
directly to 3.3 V based on the GPIO assignments above. INT/RESET assignments
refer to the adapter's compatible host-side interface. The device-tree
`vdd-supply` describes that host-side 3.3 V supply, not bare-panel VCC.

The device tree sets native portrait coordinates to 262 x 928, matching
the panel's active area. The IDF demo uses 272 x 928; confirm the touch
firmware's actual range on hardware. If necessary adjust
`touchscreen-size-x/y` in the tracked DTSI. Standard
`touchscreen-inverted-x`, `touchscreen-inverted-y`, and
`touchscreen-swapped-x-y` properties are supported. Framebuffer console
rotation does not automatically rotate input coordinates.

## Protocol and limits

The protocol follows `amoled/.../components/esp_lcd_touch_cst3530/` from
the vendor IDF sample. The [vendor repository](https://github.com/osptek/3.19-amoled-262x928-mipi-co6300)
also identifies this module's touch IC as CST3530. The supplied chip PDF
specifies up to ten contacts but does not document the report registers.

The driver reads 64 bytes using command `D0 07 00 00`, then acknowledges
with `D0 00 02 AB`. It checks report type, finger/key counts, record
bounds, coordinates and pressure before reporting Linux type-B multitouch.
Contact tracking uses position because the sample does not document contact
IDs. Unknown packet types and I2C failures release contacts to avoid stuck
presses. Key records are skipped; gesture/wake and firmware updates are not
implemented. Probe checks command acknowledgement, not silicon identity.

The read uses a combined I2C transfer with repeated START. The IDF sample
inserts 100 microseconds between its two no-STOP phases; Linux's generic
combined-transfer API has no equivalent inter-message delay. Whether the
controller needs that delay must be checked on hardware. The acknowledgement
retains the sample's 100-microsecond settling delay, and reset uses its
200 ms asserted / 200 ms released timing.

## Build and verify

```sh
./lyra-build kernel
cc -std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined \
  tests/cst3530-report-test.c -o /tmp/cst3530-report-test
/tmp/cst3530-report-test
```

After deploying a firmware image built with this kernel and connecting touch:

```sh
adb shell dmesg | rg -i 'cst3530|i2c'
adb shell cat /proc/bus/input/devices
adb shell cat /proc/interrupts
```

Expect `Hynitron CST3530 Touchscreen` and an interrupt count that increases
when touching. The small `device/rootfs/touch-test.c` utility is installed as
`/usr/bin/touch-test` by subsequent rootfs builds. A development copy can also
be pushed to the SD card and run immediately:

```sh
adb shell -t /mnt/sdcard/touch-test
# Once included in the flashed rootfs:
adb shell -t touch-test
```

It automatically finds the CST3530, or accepts `/dev/input/eventN` as an
argument. It prints `DOWN`, `MOVE`, and `UP` with slot/contact IDs, native
coordinates and pressure; Ctrl+C stops it. It does not grab the device, so
applications can continue receiving touch events. If the event queue overflows,
it exits with a message to restart instead of printing stale contact state.

Hardware validation must confirm I2C
timing, coordinate range, interrupt polarity and suspend/resume behavior.
